## 变更：在芋道项目中引入「家人在线」家族族谱模块

## 为什么需要这个变更（Why）
- PRD 定义了一个全新的「家人在线」能力：帮助同族人协同维护家族成员信息，通过可视化族谱和强审核流程进行家族文化数字化沉淀。
- 当前 OpenSpec 中尚没有与家族族谱相关的能力描述，如果直接编码实现，后端 API、数据库结构和前端使用方式容易各自为政、缺乏统一约束。
- 因此，需要一个**以规范为先**的家族模块定义，让后续后端实现与多端前端（小程序 / 管理后台）可以在统一的语义和行为之上演进。

## 会带来哪些变化（What Changes）
- 新增一个「家族族谱模块」能力规范，主要覆盖：
  - 家族创建与基础管理：创建家族申请、家族信息编辑、家族列表与搜索、隐私等级控制等。
  - 成员与树谱：以树形结构输出成员关系，支持多配偶、父子、离异等复杂关系建模。
  - 普通用户提交 + 家族管理员审核的变更流程（创建 / 修改 / 删除经审核后才影响正式数据）。
  - 性能、易用性（长辈模式）、数据安全（敏感信息加密与脱敏展示）等非功能要求。
- 明确与后续代码实现的边界与职责（本提案阶段仅定义，不落实现码）：
  - 在本仓库中新建 `yudao-module-family` 后端模块（接口定义、Service、DAL 等）。
  - 约定 App 端与管理端 API 前缀：`/app-api/family/v1` 与 `/admin-api/family`。
  - 为后续 uni-app 小程序、Vue3 管理后台等前端提供稳定的 API 契约。

## 影响范围（Impact）
- **受影响 / 新增的规范：**
  - 新增 capability：`family-genealogy`，位于 `openspec/changes/add-family-genealogy-module/specs/family-genealogy/spec.md`。
- **未来实现阶段会涉及的代码（本提案不直接改动）：**
  - 新增 Maven 模块：`yudao-module-family`（`-api` + `-biz`）。
  - 新增数据库表：`family`、`member`、`family_unit`、`audit_log`（依据 TDD 文档）。
  - 新增 App/Admin 控制器、Service、Mapper、Convert 及对应测试代码。
  - 与现有用户、权限、多租户等模块建立集成关系，但不改变其基础设计。
