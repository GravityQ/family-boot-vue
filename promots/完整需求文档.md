# 族谱项目完整需求文档

## 1. 项目概述

### 1.1 项目名称
家人在线

### 1.2 项目描述
家人在线是一个帮助同源同宗同族的人分享自己族人信息、构建家族记忆的平台。平台提供家族信息管理、成员关系管理、家族树形结构展示等核心功能。

### 1.3 项目目标
1. 帮助同源同宗同族人分享自己及家庭成员信息
2. 根据家庭成员信息构建家族关系图表（树形结构）
3. 为后续扩展功能（信息发布、社交互动等）提供基础平台

### 1.4 技术栈（建议）
- 后端：Spring Boot
- 数据库：MySQL/PostgreSQL
- 前端：Vue.js/React（后续扩展）
- 认证：Spring Security + JWT

## 3. 数据模型

| 字段名 | 类型 | 长度 | 约束 | 说明 |
|--------|------|------|------|------|

| main_surname | VARCHAR | 50 | NOT NULL | 主要姓氏 |
| description | TEXT | - | NULL | 家族描述 |
| location | VARCHAR | 200 | NULL | 家族位置（省市区/村庄） |
| creator_id | BIGINT | - | NOT NULL, FOREIGN KEY | 创建人ID（关联用户表） |

| create_time | DATETIME | - | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| update_time | DATETIME | - | NOT NULL, DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 修改时间 |
| audit_time | DATETIME | - | NULL | 审核时间 |
| auditor_id | BIGINT | - | NULL, FOREIGN KEY | 审核人ID |

- PRIMARY KEY (id)
- UNIQUE KEY (name)

## 4. 功能需求

### 4.1 家族信息管理

#### 4.1.1 家族信息列表

**功能描述：** 分页查询家族信息列表

**请求参数：**
```json
{
  "page": 1,
  "pageSize": 10,
  "keyword": "关键词（可选，搜索家族名称或姓氏）",
  "status": 1,  // 可选，筛选状态
  "location": "位置（可选）"
}
```

**响应数据：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 100,
    "page": 1,
    "pageSize": 10,
    "list": [
      {
        "id": 1,
        "name": "张氏家族",
        "mainSurname": "张",
        "description": "家族描述",
        "location": "河南省郑州市",
        "creatorName": "张三",
        "status": 1,
        "memberCount": 150,
        "createTime": "2024-01-01 10:00:00"
      }
    ]
  }
}
```

**业务规则：**
- 普通用户只能查看状态为"已通过"的家族
- 家族管理员和系统管理员可以查看所有状态的家族
- 支持按名称、姓氏、位置模糊搜索
- 默认按创建时间倒序排列

**异常处理：**
- 参数校验失败：返回400错误
- 无权限访问：返回403错误
- 系统异常：返回500错误

#### 4.1.2 添加家族信息

**功能描述：** 用户申请创建家族

**请求参数：**
```json
{
  "name": "张氏家族",
  "mainSurname": "张",
  "description": "家族描述（可选）",
  "location": "河南省郑州市（可选）"
}
```

**响应数据：**
```json
{
  "code": 200,
  "message": "家族创建申请已提交，等待审核",
  "data": {
    "id": 1,
    "status": 0  // 0-待审核
  }
}
```

**业务规则：**
- 家族名称必须唯一
- 家族名称长度：2-100字符
- 主要姓氏长度：1-50字符
- 创建后状态为"待审核"
- 需要系统管理员审核通过后才能生效

**数据验证：**
- name：必填，2-100字符，不能包含特殊字符
- mainSurname：必填，1-50字符，只能包含中文
- description：可选，最大5000字符
- location：可选，最大200字符

**异常处理：**
- 家族名称已存在：返回409冲突错误
- 参数校验失败：返回400错误
- 用户未登录：返回401错误

#### 4.1.3 修改家族信息

**功能描述：** 家族管理员修改家族信息（需审核）

**请求参数：**
```json
{
  "id": 1,
  "name": "张氏家族（修改后）",
  "mainSurname": "张",
  "description": "修改后的描述",
  "location": "河南省洛阳市"
}
```

**响应数据：**
```json
{
  "code": 200,
  "message": "家族信息修改申请已提交，等待审核",
  "data": {
    "auditLogId": 123
  }
}
```

**业务规则：**
- 只有家族管理员可以修改
- 修改需要审核，审核通过后才生效
- 修改名称时需检查唯一性
- 记录修改前后的数据到审核记录表

**异常处理：**
- 无权限：返回403错误
- 家族不存在：返回404错误
- 名称冲突：返回409错误

#### 4.1.4 删除家族信息

**功能描述：** 删除家族（软删除，需审核）

**请求参数：**
```json
{
  "id": 1,
  "reason": "删除原因（可选）"
}
```

**响应数据：**
```json
{
  "code": 200,
  "message": "删除申请已提交，等待审核",
  "data": {
    "auditLogId": 124
  }
}
```

**业务规则：**
- 只有家族管理员可以申请删除
- 删除需要审核
- 软删除，状态改为"已删除"
- 删除家族时，需要检查是否有成员，如果有成员需要先处理成员数据

**异常处理：**
- 家族下有成员：返回400错误，提示先删除成员
- 无权限：返回403错误

#### 4.1.5 家族信息审核

**功能描述：** 系统管理员审核家族创建/修改/删除申请

**请求参数：**
```json
{
  "auditLogId": 123,
  "auditStatus": 1,  // 1-通过，2-拒绝
  "auditComment": "审核意见（可选）"
}
```

**响应数据：**
```json
{
  "code": 200,
  "message": "审核完成",
  "data": null
}
```

**业务规则：**
- 只有系统管理员可以审核
- 审核通过后，更新家族状态
- 审核拒绝时，保留原数据
- 记录审核时间和审核人

        "familyUnitId": 1,

        "children": [

            "id": 3,

            "gender": 1,

            "deathDate": null,

**业务规则：**

- 支持多配偶情况（按时间顺序）
- 只返回状态为"已通过"的成员

**特殊处理：**
- 跨家族配偶：如果丈夫和妻子不属于同一家族，查询时需要关联妻子的家族信息

#### 4.2.2 添加成员信息

**功能描述：** 添加家族成员

**请求参数：**
```json
{
  "familyId": 1,
  "name": "张六",
  "gender": 1,
  "birthDate": "1990-01-01",
  "deathDate": null,
  "teamId": "第一大队",
  "familyUnitId": null,  // 可选，所属家庭ID
  "relations": {
    "fatherId": 3,  // 可选，父亲ID
    "motherId": 2,  // 可选，母亲ID（可能是其他家族的）
    "spouseIds": [4],  // 可选，配偶ID数组（支持多配偶）
    "childrenIds": []  // 可选，子女ID数组
  }
}
```

**响应数据：**
```json
{
  "code": 200,
  "message": "成员添加成功，等待审核",
  "data": {
    "id": 5,
    "status": 0
  }
}
```

**业务规则：**
- 只有家族管理员可以添加成员
- 添加后状态为"待审核"
- 如果指定了家庭关系，需要创建或更新家庭关系表
- 如果配偶属于其他家族，需要记录跨家族关系
- 姓名必填，长度2-50字符
- 出生日期不能晚于当前日期
- 去世日期不能早于出生日期

**数据验证：**
- name：必填，2-50字符
- gender：必填，0或1
- birthDate：可选，格式YYYY-MM-DD，不能晚于当前日期
- deathDate：可选，格式YYYY-MM-DD，不能早于birthDate
- fatherId/motherId：如果提供，必须存在且属于同一家族（母亲可以是其他家族）
- spouseIds：如果提供，数组中的ID必须存在
- childrenIds：如果提供，数组中的ID必须存在

**异常处理：**
- 参数校验失败：返回400错误
- 关联成员不存在：返回404错误
- 关系冲突：返回409错误（如指定了父亲，但父亲信息显示该成员不是其子女）

## 5. 业务流程

### 5.1 家族创建流程

```
1. 用户登录系统
2. 用户填写家族信息（名称、姓氏、描述、位置）
3. 系统验证数据（名称唯一性、格式校验）
4. 创建家族记录，状态设为"待审核"
5. 创建审核记录
6. 系统管理员收到审核通知
7. 系统管理员审核
   - 通过：更新家族状态为"已通过"，通知创建人
   - 拒绝：更新家族状态为"已拒绝"，通知创建人并说明原因
8. 用户可以在家族管理页面查看审核状态
```

### 5.2 成员添加流程

```
1. 家族管理员登录系统
2. 选择要添加成员的家族
3. 填写成员基本信息（姓名、性别、出生日期等）
4. 填写家庭关系（可选）
   - 选择父亲（如果存在）
   - 选择母亲（如果存在，可以是其他家族）
   - 选择配偶（可以多个，按时间顺序）
   - 选择子女（如果存在）
5. 系统验证数据
   - 基本信息校验
   - 关系数据校验（关联成员是否存在、关系是否合理）
6. 创建成员记录，状态设为"待审核"
7. 如果指定了关系，创建或更新家庭关系表和成员关系表
8. 创建审核记录
9. 家族管理员审核（可以自己审核，也可以由其他管理员审核）
   - 通过：更新成员状态为"已通过"，更新家族树
   - 拒绝：更新成员状态为"已拒绝"，通知创建人
```

### 5.3 成员修改流程

```
1. 家族管理员选择要修改的成员
2. 修改成员信息或关系
3. 系统验证修改后的数据
4. 记录修改前后的数据到审核记录表
5. 创建审核记录，状态设为"待审核"
6. 家族管理员审核
   - 通过：更新成员数据，同步更新相关成员的关系
   - 拒绝：保留原数据
```

### 5.4 跨家族关系处理流程

```
场景：丈夫属于家族A，妻子属于家族B

1. 添加成员时，如果指定配偶属于其他家族
2. 系统记录成员关系，标记为跨家族关系
3. 查询家族A的成员树时：
   - 显示丈夫信息
   - 显示妻子信息（标注所属家族B）
   - 可以通过妻子信息链接到家族B
4. 查询家族B的成员树时：
   - 显示妻子信息
   - 显示丈夫信息（标注所属家族A）
   - 可以通过丈夫信息链接到家族A
5. 根据妻子的家族ID可以查询妻子家族信息
```

## 6. 约束条件

### 6.1 数据约束

1. **家族名称唯一性**：同一系统中家族名称必须唯一
2. **成员姓名**：同一家族内，成员姓名可以重复（但建议添加其他标识区分）
3. **性别约束**：性别只能是0（女）或1（男）
4. **日期约束**：
   - 出生日期不能晚于当前日期
   - 去世日期不能早于出生日期
   - 结婚日期不能晚于当前日期
   - 离婚日期不能早于结婚日期
5. **关系约束**：
   - 一个成员不能同时是自己的父亲/母亲/配偶/子女
   - 父子关系：父亲的性别必须是1（男）
   - 母子关系：母亲的性别必须是0（女）
   - 配偶关系：配偶的性别必须与当前成员相反
   - 子女关系：子女的性别可以是0或1

### 6.2 业务约束

1. **跨家族配偶**：
   - 一般情况下，一对夫妻中，丈夫和妻子不属于同一家族
   - 查询丈夫家族信息时，需要将妻子信息添加到结果中（标注所属家族）
   - 可以根据妻子的家族ID查询妻子家族信息
   - 查询妻子家族信息时，也需要显示丈夫信息（标注所属家族）

2. **家庭关系**：
   - 一个家庭单位（family_unit）只能有一个丈夫和一个妻子
   - 一个成员可以有多个配偶（通过多个family_unit实现）
   - 子女通过family_unit_id关联到具体的家庭单位

3. **审核约束**：
   - 家族创建必须经过系统管理员审核
   - 成员增删改必须经过家族管理员审核
   - 审核通过后才能生效

4. **删除约束**：
   - 删除家族前，需要先处理家族下的所有成员
   - 删除成员前，如果成员有子女，需要先处理子女关系

### 6.3 权限约束

1. 普通用户只能查看已审核通过的家族和成员信息
2. 家族管理员只能管理自己创建的家族
3. 系统管理员可以管理所有家族
4. 所有增删改操作都需要相应权限

## 9. 错误码定义

### 9.1 错误码设计规范

**错误码范围：**
- `0-999`：系统异常编码保留（全局错误码）
- `1000000000+`：业务异常错误码（服务错误码）

**设计原则：**
- 一般情况下，使用 HTTP 响应状态码作为系统层面错误码
- 使用 0 作为成功（不使用 200）
- 业务错误码从 1000000000 开始

## 10. 数据验证规则

### 10.1 家族信息验证

- **name（家族名称）**：
  - 必填
  - 长度：2-100字符
  - 不能包含特殊字符：`< > & " '`
  - 不能全为空格

- **mainSurname（主要姓氏）**：
  - 必填
  - 长度：1-50字符
  - 只能包含中文汉字
  - 不能全为空格

- **description（描述）**：
  - 可选
  - 最大长度：5000字符

- **location（位置）**：
  - 可选
  - 最大长度：200字符

### 10.2 成员信息验证

- **name（姓名）**：
  - 必填
  - 长度：2-50字符
  - 不能包含特殊字符：`< > & " '`
  - 不能全为空格

- **gender（性别）**：
  - 必填
  - 值：0（女）或1（男）

- **birthDate（出生日期）**：
  - 可选
  - 格式：YYYY-MM-DD
  - 不能晚于当前日期
  - 不能早于1900-01-01

- **deathDate（去世日期）**：
  - 可选
  - 格式：YYYY-MM-DD
  - 不能早于birthDate
  - 不能晚于当前日期

### 10.3 关系验证

- **fatherId/motherId**：
  - 如果提供，必须存在且有效
  - 父亲性别必须是1（男）
  - 母亲性别必须是0（女）

- **spouseIds**：
  - 如果提供，必须是数组
  - 数组中的ID必须存在且有效
  - 配偶性别必须与当前成员相反

- **childrenIds**：
  - 如果提供，必须是数组
  - 数组中的ID必须存在且有效
